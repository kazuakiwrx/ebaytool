## 仕入先探し〜出品 共通手順（KOETEC版・全6タスク共通・2026-09-23制定）

yui_chan_store / kazkam の **「在庫補充」「セラーリサーチ&出品」「キーワードリサーチ&出品」計6タスク**は、
仕入先の探し方から出品（保存）までを**この章の共通手順**で行う。タスクごとに違うのは
「どの商品を処理対象に選ぶか」だけ。数値・判定がタスクのプロンプトやスキルと食い違う場合は本ファイルを優先。
※この下にある「在庫補充タスク 共通手順」以降のMONODAZ(monodaz.com)向けの章は旧版。
KOETEC(app.koetec.jp)で動くタスクはこの章を使う。

### 0. 大前提（ストア安全）
- 作業前に右上のストア名を確認し、対象ストアに `/accounts/switch?id=<ストア名>` で固定する。
  **yui_chan_storeのタスクはkazkamに、kazkamのタスクはyui_chan_storeに絶対に書き込まない。**
- ログイン画面が出たらパスワードは入力せず報告して終了。/guard が緊急停止・読み取り専用なら書き込まず終了。

- **ストアごとに専用ブラウザで作業する（2026-09-23導入）**: KOETECの「見ているストア」は
  ブラウザのクッキーごとに決まる。yui_chan_store用とkazkam用のタスクは別々のChromeを使い
  （各タスクの指示文にdeviceIdを記載）、これにより両ストアの同時作業ができる。
- **KOETECの在庫監視の巡回（/monitor）が動いていても作業を続けてよい（2026-09-24変更）**。
  「仕入先取得」は巡回とは別のブラウザプロファイルで動くようになったので、巡回中でも弾かれない。
  スキルやタスク指示に「巡回中なら報告して終了」と残っていても、この行を優先する。
  もし「巡回中は仕入先を取得できません」と出たらKOETECが古い版のままなので、その旨を報告して終了。
- **保存時に「ストアが切り替わっています」と出たら**、その書き込みはKOETEC側で中止されている
  （商品変更画面・アラート削除にストア照合ガードあり）。慌てず、正しいストアに固定し直して
  画面を開き直す。ガードに任せて別ストアへ書き込もうとしない。

### 1. 仕入先の検索（複数条件×同時検索。Pythonでは行わずClaudeがブラウザで行う）
- **検索先はメルカリとYahoo!フリマ(PayPayフリマ)の2サイト**（2026-09-23 ユーザー指示）。
- **検索キーワードは4種類以上**作る。優先順:
  (1) **型番・品番単体**（あれば最優先。言語非依存で最も精度が高い）
  (2) **日本語の正式名称**（eBayの英語タイトルを日本語へ。例 "Godzilla Soft Vinyl"→「ゴジラ ソフビ」）
  (3) ブランド/シリーズ名＋キャラ名・モデル名（日本語）
  (4) 短いコア語のみ
  商品名がそもそも英語表記の商品（海外ブランド・型番英数字がそのまま通用するもの）は英語でも検索。
  **長い検索語はヒットしないので2〜4語程度に絞る**。From Japan / F/S / NEW 等のeBay定型句は除去。
- **同時検索**: キーワード×サイトの全組み合わせ（4キーワードなら8タブ）を
  **browser_batchでtabs_create→navigateをまとめて発行し、一気に開いて並行で読み込む**。
  検索URL直指定: メルカリ `https://jp.mercari.com/search?keyword=<URLエンコード>&status=on_sale` ／
  Yahoo!フリマ `https://paypayfleamarket.yahoo.co.jp/search/<URLエンコード>?open=1`
  開いたタブを順に読んで候補（商品名・送料込み価格・URL）を集める。
- **1商品の検索が終わったら、その検索タブを必ず閉じてから次の商品へ**（タブを溜めない）。

### 2. 候補の選定
- **モデル違い・型番違い・セット内容違いを仕入先に入れない**（合わない候補は除外）。
- 即決・在庫ありのみ。掲載6カ月以上前は対象外（鮮度ルール）。コンディションはeBay側と一致。
- 残った候補を**送料込み価格の安い順**に並べ、安いものから商品ページを開いて
  在庫あり・**写真でeBay出品と同一商品**であることを確認できた最初の1件を採用。
- 別商品だった／取得できなかったら次に安い候補を試す（1回のNGで諦めない）。
- **2サイト×全キーワードで見つからなければ「仕入先なし」として次の案件へ**（エラー扱いにしない。
  報告に試したキーワードを残す）。

### 3. 出品（KOETECの商品変更/出品画面）
1. 採用した仕入先URLを入れて「仕入先取得」→ 出てきた写真・商品名で**同一商品かを最終確認**。
2. **価格**（タスク別の価格ルール）:
   - **在庫補充**: 利益率8〜15%（狙い11.5%）に入る価格。画面の利益率実値で確認し、届くまで上下する。
   - **セラーリサーチ&出品／キーワードリサーチ&出品**: eBay Sold検索の**現行最安値−$0.50**を基準に、
     利益率8%以上を満たすこと（満たさなければ満たすまで上げる。上げても売れない水準なら見送り）。
   - **利益率が目標未達・マイナスのままでは絶対に保存しない。**
3. **画像入替**: 新仕入先の写真に入れ替える。ただし**既存写真にyui_chan_storeのロゴ／
   ウォーターマークがあるものは入れ替えない**（最優先）。仕入先側写真に他店ロゴがあれば使わない。
4. **数量**を規定値に戻す。
5. 保存。**価格を変えるとシッピングポリシーは新しい価格の価格帯に合うものへKOETECが自動で
   選び直す**（2026-09-23実装）ので手動選択は不要だが、保存結果にエラーが無いか確認する。
   保存はガードを通る。弾かれたら無理に通さず保留にする。

### 4. チェックNGで終わらせない（2026-09-23 ユーザー指示）
確認に引っかかったら直せるものはその場で直して出品まで進める（別商品→次候補、価格→調整、
ポリシー→自動選び直し）。**例外として保留（人の判断）にするのは**: 仕入価格（送料込み）¥100,000以上／
価格差ルール超過／利益率がどうしても届かない／ガードに弾かれた、の4つだけ。

#### 非USD出品（米国以外のeBayサイトの多サイト展開分）は対象外
保存時に「**この出品は米国サイトではありません（通貨 EUR/CAD等）**」と出た商品は、
yui_chan_storeの多サイト展開分（eBayカナダ・ヨーロッパ等の現地通貨の出品）。
KOETECの価格計算はUSD前提のため価格改定できない（2026-09-23、eBayエラー10065対策として
KOETEC側でブロックするよう実装済み）。**修正を試みず「非USD対象外」としてスキップ**して
次の案件へ（保留ではない。アラート起点の場合アラートは残す）。報告に「非USD対象外 n件」を書く。

### 5. ローテーションと後片付け
- **直近1週間以内に一度見た商品はスキップ**し、全体を一巡させる（同じ商品ばかり何度も見ない）。
- 1回の実行の処理上限（2026-09-23 ユーザー指定）: **在庫補充（quantity=0起点／アラート起点とも）は最大50件**、
  **セラーリサーチ・キーワードリサーチは候補チェック最大50件**（出品数はカテゴリ別1日20件の上限内で、
  条件を満たした分だけ）。アラート起点の在庫補充は**出品できた商品のアラートだけ削除**し、
  出品まで至らなかった商品（保留・仕入先なし・スキップ）のアラートは残す。
- 終わったらこの実行で使ったタブグループを必ず閉じる（どの終わり方でも）。

### 6. 梱包サイズの確認（2026-09-23 ユーザー指示・全タスク共通）
- **Claudeが仕入先を決定（新規採用・選び直し）した商品だけ**行う。商品変更画面の
  「梱包サイズ・重さ」欄に**既に値が入っていればスキップしてよい**。
- 調べ方: 型番・品番（なければ商品名）で検索し、**メーカー公式サイトかAmazon.co.jpの商品ページ**の
  仕様表から商品本体の寸法・重量（商品サイズ）を数値で確認する。
  **仕入先（メルカリ・Yahoo!フリマ等）のページの記載は使わない。**
- **公式サイト・Amazonのどちらでも見つからない場合**、次にGoogleで「商品名（＋型番） 梱包サイズ」で
  検索し、**ChromeのAI回答（検索結果に出るAI要約・「質問する」欄の回答）を確認してよい**。
  ただし**数値が明確で、出典（メーカー名・型番の一致）がはっきりしている場合だけ採用**する。
  「〜と思われます」「一般的には」等のぼかした言い回しや、根拠が示されない・型番が一致しない
  など**少しでも不確かな回答は不採用**とし、無理に使わず下の「特定できなかった場合」の扱いにする。
- **商品サイズをそのまま使わず梱包サイズに換算**する: 外寸は各辺+2〜5cm（小物+2cm・大きめ+5cm）、
  重量は+100〜300g（箱・緩衝材分）。
- 記入先: **商品変更画面の「梱包サイズ・重さ」欄**（KOETECの/sizecheck欄＝サイズ確認待ちリストは
  2026-09-23廃止）。記入者は**「Claudeが判断」**を選び、根拠・出典を必ず一言書く
  （例:「公式25×15×5cm/320g→梱包目安30×20×8cm/500g」）。保存すると送料計算と
  quantity=1復帰の判定に使われる。
- **特定できなかった場合**（公式にもAmazonにも記載なし・廃盤等）: 無理に推定せず、その商品は
  **保留**（出品復帰しない。アラート起点ならアラートも残す）にしたうえで、
  **在庫補充トラッカーの「商品サイズ確認待ちリスト」に登録する**（2026-09-24変更）:
  - **KOETECの商品変更画面で、「梱包サイズ・重さ」欄の「根拠・出典」に見つからなかった理由と
    調べた場所を書き、「サイズ確認待ちリストに登録」ボタンを押す。** KOETECがGitHubに書き込む。
    **ClaudeがGitHubトークンを取り出して git push する必要はない（しない）。**
    すでに登録済みなら「すでにあります」と出るだけなので、重複を気にせず押してよい。
  - 人向けの一覧は GitHub Pages の `size_pending.html`。人はここを見て寸法を確認し、
    KOETECの商品変更画面から記入者「人が確認」で記入する。
- **リストの掃除（在庫補充タスクのみ）**: 実行の冒頭で、担当ストアに固定したブラウザで
  **KOETECの `/sizepending/sync` を開くだけ**（梱包サイズ記入済みの商品をKOETECがリストから消す。
  他ストアの項目には触らない）。「解決済み X 件を削除、残り Y 件」を報告に書く。
  （config を読むための git clone は従来どおりでよいが、size_pending.json への push は不要になった）

### 7. 出品対象・除外（カテゴリ/ブランド）
- **トレーディングカード（ポケモンカード等）**：鑑定（グレーディング：PSA/BGS等）付きに限り出品OK。鑑定なしの生カードは対象外（スキップ）。eBay側・仕入先側ともに鑑定品であることを確認する。
- **コミック（本・漫画）**：出品禁止（対象外＝スキップ）。
- **Gucci／Louis Vuitton（ルイヴィトン）**：出品対象（OK）。
